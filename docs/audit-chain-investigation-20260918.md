# 本地审计链异常排查

依据用户提供的新测试报告摘要，于 2026年9月18日核验 cyberguard-preview 数据库。报告提及的 cyberguard_test_report.md 未在仓库和 Downloads 中找到，因此本记录只描述摘要对应问题与直接数据库核验结果。

初次只读检查共 10676 条已签名记录，全部为 chain_version 2。前后记录链接错误为 0，记录内容与签名不匹配共 51 条，最早异常为 ID 13540，时间 2026年9月16日04时17分06秒。

这 51 条记录的 user_id 均为空。逐条只在内存中代入候选原用户 ID 后，全部可以复现原始 entry_hash，没有无法解释的异常。对应 ID 为 17、18、19、20、27、28、29、30、31、34、40。数据库实际外键 audit_logs_user_id_fkey 配置为 ON DELETE SET NULL。由此可确认异常内容是已签名的 actor ID 被清空，且高度符合测试用户硬删除触发外键置空的机制；本次检查不能独立证明历史删除操作由谁执行。

当前修改新增迁移 047_preserve_audit_actors，将该外键改为 RESTRICT，并对 User.audit_logs 设置 passive_deletes="all"，避免 ORM 在删除用户时先把审计外键清空。数据库直接删除和已加载关系的 ORM 删除均由回归测试覆盖。停用用户不会改动其审计记录。没有已持久化审计记录的用户若在缓冲刷盘前消失，原有缓冲处理仍能在签名前清空失效引用。

已有历史记录、entry_hash 和 prev_hash 未修改，验证仍应报告原有异常。修复阻止再次由账号清理产生此类内容变更，并不把历史异常宣称为已修复。后续如需恢复，应先保全当前数据库及签名，核对删除前备份并形成可追溯恢复方案。不得直接重签历史链来掩盖异常。
