# 07 · 功能对照矩阵

状态：定稿 · 按 standalone-first 重排

**这是防止范围蔓延的主要参照——想给桌面端加功能前先查这里。**

## 判读方式：两个维度

功能归属由**运行态**和**模式**共同决定，不是单一的"下放/不下放"。

| 维度 | 取值 |
|---|---|
| 运行态 | `standalone`（默认，自洽完整）· `connected`（可选增强） |
| 能力档位 | **只读咨询** · **完整作业**（默认）。会话创建时确定，**不是互斥角色**——单兵两类工作都做，见 DEC-027 |

图例：**✅ 有** · **⚠️ 形态不同** · **🕓 首版不做（排期）** · **❌ 不做（原则）**

> **🕓 与 ❌ 的区别很重要**：🕓 可以做但没排上，将来可加；❌ 做了就破坏产品逻辑或合规前提，永远不加。

### 判断标准

**不是**"这个功能在概念上属于组织还是个人"，**而是**"没有它，单机用户能不能把活干完"。

> 早期版本用的是前者，等于从现状倒推归属（"服务端有审批队列，所以审批属于服务端"），而不是从用户需求正推。这导致审批、GRC 工作台、审计查询、态势聚合、知识库、Provider 配置六项被整批误判为不下放。

> ⚠️ **本文早期版本按"服务端 × 节点"编排，已按 DEC-022 重排。** 当时标为 ❌ 不下放的一批（审批、GRC、审计查询、态势聚合、知识库、Provider 配置）在 standalone 下**必须下放**，否则单机版不完整。

---

## 1. 共用内核（`packages/agent-core` + `packages/llm-router`）

服务端与桌面端跑同一份代码，不是两套实现。

工具调用循环、循环守卫（参数指纹归一化）、反思器、工具预算、上下文压缩、tool result 截断、LLM 重试退避、自动续跑、统一 Provider 路由。

**端口需两套完整实现**（DEC-022）：

| 端口 | 服务端 | **单机（必须完整，不是薄壳）** |
|---|---|---|
| `Store` | Postgres | SQLite + 树状 JSONL |
| `VectorIndex` | pgvector | **本地向量库** |
| `TaskQueue` | Celery + Redis | APScheduler |
| `Bus` | Redis pub/sub | 进程内 asyncio |

## 2. standalone 必备（没有它产品不完整）

| 功能 | 档位 | 说明 |
|---|---|---|
| 本地经验库 | 两者 | 反转自原设计。断网可用，上传须逐条确认（INV-11） |
| 本地会话树 | 两者 | append-only JSONL + `leaf_id`，可 fork |
| 本地审批与自批准标注 | 两者 | `approval_type: self`，界面显示"自批准"（INV-06 / INV-38） |
| 审计哈希链 | 两者 | tamper-evident，可选外发 SIEM。**不得宣称等同 WORM** |
| 带凭据 MCP | **核心** | Keychain 独立 slot。**单兵的全部外部数据都靠它**聚合 SIEM / 云平台 / 漏扫 / 工单 |
| 内置安全 SOP 技能集 | 两者 | 开箱可用。空技能池 = 产品未完成 |
| 本地知识库 / RAG | 两者 | 本地建库，不依赖服务端 |
| Provider 配置 | 两者 | 本地配置，凭据进 Keychain（DEC-017） |
| 报告生成 | 两者 | artifact 带 sha256 与保留期，**不出网**（INV-12） |
| 态势聚合 | 两者 | **数据来自 MCP 接的外部系统，不是服务端**——SIEM 告警、云配置风险、漏扫结果、工单进度本就在客户环境里，直连比绕服务端还少一跳 |
| **合规工作台** | 两者 | 框架知识、控制项清单、差距分析、证据整理、审计材料生成。**独立顾问的主要工作就是这个**，单机上完全成立。与"组织级合规态势"不是一回事，见 §3 |
| **审计查询** | 两者 | standalone 下本地哈希链**就是唯一审计源**。"上周我让 agent 做了什么"是复盘与取证的基础。能力与 connected 相同，**可信度不同**（tamper-evident vs tamper-proof） |
| 本地工具执行 + 沙箱 | **仅完整作业档** | 需 M2 全部判据通过才解锁（DEC-021） |
| 证据浏览器 | 仅完整作业档 | 只读挂载 + sha256（INV-04） |
| Plan Mode | 两者（MCP 侧动作同样有副作用） | 不可逆动作执行前审批（INV-19） |
| Trust Gate | 两者 | 不可信目录的本地资源默认不加载（INV-14） |

## 3. connected 增强（服务端的五条不可替代能力）

见 DEC-023。**服务端不是技术必需品，是合规与协作必需品。**

| 能力 | 为何单机做不到 | 与 standalone 对应项的关系 |
|---|---|---|
| **职责分离审批** | 批准者 ≠ 操作者。单机上任何方案都是自批自，拓扑决定 | standalone **有审批**（防 agent 出错），缺的是**职责分离这个属性**（防人越权） |
| **不可篡改审计** | 日志不能在被审计者机器上。本地哈希链能证明未被改，但可整条删除重开 | standalone **有审计与查询**，缺的是**不可篡改这个属性** |
| **跨人共享** | 经验、技能、知识、事件上下文 | standalone 有本地经验库，缺的是跨人 |
| **组织级合规态势** | 多部门控制项归属、跨团队证据收集、审计员视角的实时覆盖率 | standalone 有**合规工作台**（个人/顾问视角的差距分析与材料生成），缺的是全组织实时数据 |
| **强制策略（L1）** | 中心下发才能形成可审计的受控状态 | standalone 有本地策略，但用户自己能关——**不构成安全边界**（INV-38） |

> **注意这张表的第三列。** 反转的是**功能本身**，没反转的是它的某个**属性**。"审批"和"职责分离"是两回事，"审计查询"和"不可篡改"是两回事——把它们当成一件事，正是早期版本整批误判的根源。

另有三条"能做但集中更划算"：凭据集中管理与轮换、服务端能到而节点到不了的网络位置（`governed` 代执行的真实价值）、定时与长时任务。

**强制策略三级取舍**：L1 收紧执行策略 ✅ / L2 收走全量数据 ❌（与 INV-10 冲突）/ L3 远程控制 ✅。

## 4. ❌ 不做（原则问题）

> **❌ 有三类，不要混为一谈**——早期版本正是因为混了才整批误判：
>
> 1. **拓扑上不可能**（职责分离、不可篡改、跨人共享）→ 归 §3，是 connected 的价值，不是"不做"。
> 2. **概念上不成立**（RBAC / SSO / 多用户管理）→ 单机只有一个用户，概念本身没有意义。
> 3. **做了就破坏产品逻辑或合规前提** → 才是下表这一类，**永远不加**。

| 功能 | 原因 |
|---|---|
| RBAC / SSO / 多用户管理（standalone） | 第 2 类：单机只有一个用户，概念不成立。connected 下由服务端提供 |
| 节点间 LAN 自动发现 / P2P | 企业网内的横向移动通道（INV-09） |
| 公网可访问的 artifact URL | 取证报告不得出网（INV-12） |
| 节点子 agent spawn | 每多一个权限主体，审计成本上一台阶（INV-22 / DEC-012） |
| 自动学习闭环（agent 自建并自用技能） | 自我提权 + 持久化后门（INV-20 / DEC-013） |
| 扩展与技能热重载 | 绕过审批的能力变更通道（INV-26） |
| connected 下上传全量会话 | L2，与 INV-10 冲突；会把产品做成监控软件 |
| 上架 App Store | 强制 App Sandbox，跑不了本地扫描工具（DEC-026） |

## 5. 🕓 首版不做（排期，非原则）

**不要在 M1–M5 期间擅自加入。**

| 功能 | 备注 |
|---|---|
| 抓包类工具本地执行 | 需 `/dev/bpf*` 特权辅助进程，抬高安全评审门槛（DEC-009）。connected 下走集中代执行 |
| OCR / 附件深度解析 | 原生扩展打包痛点，已从 sidecar 依赖裁剪 |
| **操作 Profile** | "日常调查" / "应急响应已授权"一键切换沙箱+审批档位。**勿与首版必需的 LLM Profile 混淆**（DEC-017、09 §6.3） |
| **本地定时任务** | 本地 APScheduler 能跑，但应用不在前台或机器睡眠时不可靠。**可做，只是不作为首版承诺**——早期版本标 ❌ 是不准确的，它不是原则问题。可靠的定时属于 connected（服务端 24h 运行） |
| 确定性 Workflow 编排 | 安全 SOP 顺序不该每次让模型发挥 |
| 本地个人偏好层 | `MEMORY.md` 索引 + pruning（与本地经验库分层，见 `08-MEMORY.md`） |
| `/remember` 显式标注 + 失败经验记录 | 顺带修 `_maybe_record_episode` 硬编码 `success=True` 的缺口 |
| Windows / Linux | 二期，见 `03-ROADMAP.md` |

---

## 6. 一句话总结

**standalone 让一个人把活干完并留下可信记录；connected 让一个组织证明这些活是受控的。**

前者卖生产力，后者卖可证明的合规性。
