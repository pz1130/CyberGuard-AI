# 12 · M1.5 黄金路径（产品验证）

状态：定稿 · 2026-07-30  
前置：M0a 内核抽取 + M1 壳/骨架（mock）完成后进入；本文现在就写，是为了 **M0a 抽取时知道边界，不为桌面端提前写功能**。

## 一句话

**开发者自己用桌面 App 完成一次真实的「告警分诊 → 只读调查 → Markdown 报告」闭环，并愿意第二天再打开。**

产出不是代码清单，是判断：方向对不对、数据源/技能该怎么收。

---

## 黄金路径（唯一验收场景）

| 步骤 | 做什么 | 成功判据 |
|------|--------|----------|
| 1. 起会话 | 打开桌面 App，选「完整作业」或默认档位，接好真实 LLM | 流式输出可见 |
| 2. 接数据 | 接 **1–2 个** MCP 数据源（优先：日志/告警类；次选：漏洞/资产只读 API） | 工具列表里能看到 MCP 工具 |
| 3. 下任务 | 用户输入类似：「这批告警里哪些值得优先处理？给出理由与建议动作」——可粘贴告警片段，或让 agent 从 MCP 拉 | Agent 进入执行循环，有工具调用时间线 |
| 4. 只读调查 | Agent 只读查日志/告警/CVE 上下文，**不改主机、不拦流量、不写生产** | 无本地破坏性 Exec；高危意图应被 Plan/确认拦住（若 M1.5 尚未有 Plan，则人工盯住） |
| 5. 出报告 | 产出 **Markdown** 报告：结论 + 排序 + 证据引用（来源/查询摘要；有文件则哈希） | 报告可复制；引用可回溯到工具结果或粘贴原文 |
| 6. 再打开 | 同一人或另一安全从业者愿意用它做**第二件**真实小事 | 反馈清单 ≥ 5 条「好用/别扭」 |

**明确不是黄金路径的**（M1.5 不做完也不验收）：

- 21 个 Web Tab 的桌面复刻  
- 组织级 GRC / 审批队列 / SSO / WORM  
- 沙箱逃逸对抗、签名公证、可分发安装包  
- 多 Agent 群聊对辩（可做实验，不挡出口）

---

## 数据源与技能（先窄后宽）

按「广而不深」+ 开放问题 C：

1. **MCP**：通用性最强的 1–2 个（例如 SIEM/日志查询、或通用 HTTP/API 连接器 + CSV 导入兜底）。**不深集成某一家厂商。**
2. **内置 SOP 技能（极少）**：  
   - 告警分诊（severity）  
   - CVE 影响粗评（可选第二条验证任务）  
3. **产出**：仅 Markdown；模板系统等有人抱怨再说。

自用验证时你实际接什么，就是第一批数据源答案——写回 `11-OPEN-QUESTIONS.md` §A/C。

## 与 M0a / M1 的关系

| 阶段 | 为黄金路径准备什么 |
|------|-------------------|
| **M0a-1** | `llm-router` / `agent-core` 包边界；工具五步管线**骨架**；审计事件流占位。行为零变化。 |
| **M0a-2** | 参数校验、默认串行、结构化错误、压缩加固（Constraints 不丢授权）。 |
| **M1** | Electron + sidecar + 单工作台；mock LLM/工具跑通循环；无真实本机破坏性工具。 |
| **M1.5** | **本黄金路径**；真实 Provider + 真实 MCP；禁止分发；明示无沙箱/无静态加密。 |

M0a 期间**不写桌面代码**；但抽取时问自己：这段逻辑是「单兵任务循环」需要的，还是「服务端 21 Tab 运营」专属的？后者留在 `app/`。

## 硬约束（INV-38）

- 构建产物标记开发版，**禁止分发**  
- 启动明示：未启用沙箱与静态加密，**勿处理真实敏感生产数据**  
- **不宣称**任何安全属性（不宣称就不算伪装）

---

## 出口时要写下的判断

1. 这条路径是否比「开浏览器用 Web 后台」更值得为单兵做桌面？  
2. 卡在哪：MCP 覆盖、技能内容、上下文压缩、审批打扰、还是 UI？  
3. M3 范围要砍什么、补什么（尤其数据源与技能）？  
4. 「多 Agent 对辩 / agent-vs-agent」是否进入核心交互，还是保持辅助？（见 `11-OPEN-QUESTIONS.md` §G）

方向不对就掉头——成本远低于做完 M3 再掉头。
